# 群调度语言与硬编码检查（2026-09-23）

本次覆盖群调度、旧兼容入口、应用通知、自动任务提议，以及独立游戏验收引擎；不将第三方模型回复质量当作界面多语言保证。

## 已处理

- 决策设置及调度通知接入中英文词典。新通知保存模板参数；旧版 Foundry 系统通知在显示时按已知模板转换，聊天数据库原文不改写，真人和模型内容不翻译。成员名中的占位符不会再次插值。
- 删除中英文静默关键词、自动任务创建关键词门槛、游戏消息拦截。是否回复由配置决策策略决定；共享多人群使用下述显式调用规则。
- 自动任务创建使用原始真人请求语义和结构化提议，并在创建前独立核验。模糊、非法 JSON、核验失败均不创建；普通回复不额外调用核验。核验使用隔离本地 CLI 请求和禁止工具的提示，其原生工具约束仍取决于该适配器，不能等同系统级无工具沙箱。
- 移除生产调度提示词中的报数、笑话、谁是卧底、狼人杀等专用示例／路由。Jev 的 `ordered` 是通用顺序参与分类；普通模型也使用通用 `participantScope`、`participationOnly` 和完成进度。
- 执行器不再分配 `rollCallNumber` 或硬生成回复数字。成员获取当前任务成功结果的 ID 和数量，按用户要求继续。旧 `rollCall` 只保留日志迁移，不用于触发新任务。
- 公开交付使用结构化 `publicDeliverables`，不靠隐私词表推断；能力排序使用 Unicode 分词辅助，跨语言语义由模型判断。澄清提问支持多种语言问号。
- 独立游戏验收引擎通过结构化 `start` 调用，不解析聊天关键词。中英文规则、裁判文案、词库和错误已分离；语言随状态持久化，控制流程使用稳定错误码而非中文错误文本。游戏规则仍仅属于测试引擎。
- 本轮发现的应用自有静态中文异常改为英文错误键及中文显示映射，相关错误视图调用翻译。第三方原始诊断保留原文。

## 多真人共享群

删除“无 @ 就调用自己第一个 Agent”的默认路径及旧会话自动续接。普通消息、只 @ 真人、引用中的 @、`@all` 不启动 Agent；显式 @ Agent 或选择任务接收者才调用。跨主人权限、服务端任务认领仍保留，同名歧义会拒绝派发。两个发送入口一致，接收者选择器发送成功后重置。详情见 [共享群协议](social-chat.md)。

单人和自己的多个 Agents 组成的本地群继续使用所配置的决策方式。未实现跨账号智能参与模式或分布式 Leader 选举，不将本地群调度误称为共享群分布式调度。
